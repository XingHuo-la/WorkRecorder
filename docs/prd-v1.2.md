## 一、版本目标

1. **一篇笔记可以同时挂在多条记录上**：记录里能看到它的全部笔记，笔记里能看到它挂在哪些记录上，任意一条都能单独解除。
2. **打开记录抽屉先看到结论**：标题、状态、正文落在第一屏，字段与子项按需展开，不再"打开抽屉先看到一张表单"。
3. **笔记页变成"打开就写"**：一屏里只有标题、一行元信息和正文，两行工具栏与三个下拉不再挤占写作空间。

## 二、用户故事

1. 作为台账使用者，我想把一份故障分析笔记**同时挂到"设备 / 事件 / 复盘"三条记录上**，以便不用把同一段内容复制三份。
2. 作为记录者，我想在一条记录里一眼看到**挂了哪几篇笔记、各叫什么、最近什么时候改的**，以便决定打开哪一篇。
3. 作为记录者，我想在笔记页看到**这篇笔记目前挂在哪些记录上**，并能单独摘掉其中一条，以便纠正挂错的地方。
4. 作为诊断者，我想**打开一条记录就能读到结论正文**，不用先滚过六个字段和四个子项，以便快速判断。
5. 作为作者，我想**打开笔记就能直接写**，分类和按钮不占正文空间，以便写长文时眼睛不累。
6. 作为长期使用者，我想记录被删掉后笔记上**还留着「已删除记录（原 #37）」的痕迹**，以便知道当初为什么写它。
7. 作为用 Typora / 资源管理器整理文件的人，我想**移动或重命名笔记文件后关联还在**，以便不被软件的文件布局绑架。
8. 作为从记录跳到笔记的人，我想**写完一键回到刚才那条记录**，以便接着改字段。

## 四、两个界面的信息优先级与交互流

### 4.1 记录详情抽屉（`src/rowDrawer.js` + `sheetPanels.openDrawer`）

**现状证据（可逐条核对）**

- 区块顺序按 `rowDrawer.js:178-211`：面包屑 → 提示条 → **字段网格** → **子项** → **挂载的表** → **正文** → **关联笔记** → **被引用于** → 动作按钮；footer 是「删除记录 / 上一条 / 下一条」。
- 截图 `_debug/shots/drawer-row.png`（1360×860，标准深色）：大标题「2 号机组前置泵驱动端轴承」下方，6 个字段各占一整行，其中第 1 个「设备名称」的值与大标题**逐字相同**；接着 4 个子项、1 张挂载表；**正文只露出「结论」+ 一行**；「关联笔记」「被引用于」两整块都在折叠线以下。
- 抽屉是固定窄栏（`DRAWER_WIDTH = 560`），字段行是「固定宽 label + value」，长值只能换行。

**首要任务**：读/写"这条记录说了什么"。其次是"它属于哪、下面有什么"。最后才是"它还牵连到什么"。

**一屏从上到下（新的可见顺序）**

1. **标题（可点改）+ 右侧状态 chip**。状态是台账里最常扫的信息，不该混在字段网格里当第 3 行。
2. **一行元信息**：表名 · 第 x / y 条 · 祖先路径（有祖先才显示，中间层用「⋯」省略）。面包屑从独立一行降级为这一行里的一段。
3. **正文**。Markdown 渲染；长文默认收在约 6 行的预览高度，底部一个「展开全文」；空态是可点的「写点什么…」。
4. **关键字段**（最多 5 个）：数值类、日期/时间类、状态类优先，文本类其次。判定用字段类型，不靠用户手工排序。
5. **笔记 · N 篇**：每项「标题 + 更新日期 + 一行摘要」，末尾固定一个「＋挂一篇笔记」。
6. **结构 · N 个子项 · M 张表**：默认收起，展开后是原来的两段列表（列表本身的渲染不动）。
7. **被引用于**：仅非空时出现。

**哪些内容被降级 / 收起**

| 旧区块 | 处理 | 理由（有据） |
|---|---|---|
| 字段网格里的标题字段 | **删** | 截图里「设备名称」与大标题逐字重复，纯粹占一行 |
| 第 6 个及以后的字段 | **收进「更多字段」** | 6 个字段各占一行，正文被挤到折叠线下（`styles.css:14540` 的注释已经记过这个坑："6 个字段吃掉 300px、正文被挤到折叠线以下"） |
| 子项（4 项占约 140px） | **并入「结构」并默认收起** | 子项是"下一步要看"的东西，不是"这条记录是什么" |
| 挂载的表（1 张卡片） | **并入「结构」** | 一屏只挂一张表，却占一整块带头部的版面 |
| 被引用于（空态） | **非空才渲染** | 现在无引用也渲染「暂无引用」，空块也吃高度 |
| 动作按钮（转待办 / 转笔记 / 修改分类 / 编辑） | **收进 footer 的「⋯」菜单** | 兼容壳塞进来的 4 个按钮平铺在正文下方，和"读这条记录"无关 |
| footer 的「删除记录」 | **收进「⋯」** | 危险操作不该和"下一条"并排，误点成本高 |

**编辑与查看如何切换**

- **不引入"编辑模式"开关**。查看态就是完整的：正文全文可读（长文只是折叠，不是隐藏）、字段值可读。
- 编辑保持"点哪儿改哪儿"，且把"要滚动才够得到"的成本消掉：
  - 点标题 → 就地输入框（Enter 保存 / Esc 放弃）——现状保留；
  - 点正文 → 变 textarea（Ctrl+Enter 保存 / Esc 放弃原值）——现状保留，不改成 blur 保存（`rowDrawer.js:1396-1403` 的取舍有理由：blur 早于 click，会和"切换记录"打架）；
  - 点字段值 → 单元格编辑器 —— 现状保留。
- 结论：抽屉里**不需要新增任何"进入编辑"的按钮**，需要改的是入口位置——正文与笔记区上移后，一次点击即达。

**空白态怎么表现**

- **无字段记录**（随手记 / 待办 / 子项）：现在 `renderMetaRows`（`rowDrawer.js:608-637`）会拼一屏「类型 / 状态 / 标签 / 发生时间 / 截止 / 备注 / 所属表」，对刚建的记录几乎全是空的。改为：状态进标题行右侧 chip，时间与标签进元信息行，**空值一律不占行**。
- **无正文**：保留「写点什么…」这一行可点提示（现状已经是入口，不动）。
- **无笔记**：区标题写「笔记 · 0」，下面一行虚线「＋挂一篇笔记」。不写「还没有关联笔记」这种纯陈述。
- **无子项且无表**：「结构」块整块不出现（不显示"0 个子项"）。

### 4.2 笔记页（`#subview-notes` / `src/notesEditor.js`）

**现状证据（可逐条核对）**

- `index.html:408-469` 的结构是四层：① 页头（10px 的 `NOTES` kicker + `h1 笔记` + 一句说明 + 右上「打开文件夹」「新建笔记」）→ ② 工作台（左侧固定列：筛选框 + 计数 + 列表；右侧：**工具栏**（标题输入 + 类型/主分类/子项目三个下拉）→ **第二行**（状态文字 + 隐藏预览 / 在外部打开 / 删除 / 保存）→ **恒等分双栏** Markdown | 预览，各带一个小标签）。
- 截图 `_debug/shots/notes.png`：左侧面板写着「还没有笔记 · 点右上角「新建笔记」开始」，右侧大片空态写「选择或新建一篇笔记」——两块空态在说同一件事，而真正的按钮在页面最右上角，视线要跨过整个屏幕。
- `notesEditor.js:22` 已经有 1200ms 自动保存，同时 `:341 saveCurrentNote` 又挂了「保存」按钮——两套保存语义并存。
- 现状笔记页**没有任何位置**显示"这篇笔记挂在哪些记录上"：`record_id` 只在抽屉侧被读取（`rowDrawer.js:836` 的筛选、`notesStore.js:214` 的写入）。

**首要任务**：写。第二是"这篇笔记在为哪条记录服务"。第三才是分类元数据。

**一屏从上到下（新的可见顺序）**

1. **一行顶栏**：`←`（仅当从记录进来时出现）· **笔记标题**（无边框、直接改、视觉上就是这一屏的主标题）· 右侧「源码 / 预览」一个切换 · 「⋯」更多（打开文件夹、在外部打开、删除）· 保存状态小字（`已保存 14:32` / `未保存`）。
2. **关联记录行**：chips（记录标题；点开抽屉，× 解除）+ 末尾「＋挂到记录…」；未挂任何记录时只显示入口。
3. **正文**：源码或预览，占满剩余全部高度。
4. **底部一行只读信息**：字数 / 更新时间。不承载任何操作。

**哪些内容被降级 / 收起**

| 旧区块 | 处理 | 理由（有据） |
|---|---|---|
| 页头 `NOTES` kicker + 说明句 | **删** | 10px 英文 kicker 是纯装饰；说明句对单用户是噪音 |
| 页面级「新建笔记」按钮（右上） | **移入编辑器 / 空态** | 它与正文区隔了整个屏幕，新建后还要把视线拉回来 |
| 「保存」按钮 | **删** | 自动保存 1.2s 已覆盖；留着只会让人怀疑自动保存 |
| 类型 / 主分类 / 子项目三个下拉 | **降级**：默认收起为标题下方一行「分类：设备 / 给水系统」，点一次展开修改 | 三个并排下拉与标题同层，等于把元数据抬到最高优先级 |
| 第二行工具栏（隐藏预览 / 在外部打开 / 删除） | **并入「⋯」** | 一行里 4 个按钮争位置，其中 3 个是低频操作 |
| 「Markdown」「预览」两个分区小标签 | **删** | 切换控件本身已经说明当前在哪个视图 |
| 恒等分双栏 | **改为单栏 + 一键切换**（宽屏可记忆双栏偏好） | 窄屏下源码栏只剩半屏，长文写不动 |
| 列表项里的 70 字摘要 | **删**，列表项压到 2 行 | 280px 宽下摘要只能显示两行，扫读时它是噪音不是线索 |

**编辑与查看如何切换**

- **默认就是可写的**：打开笔记 = 源码视图 = 可以立刻敲字，不出现"点一下进入编辑"这一步。
- 预览是**切换**而不是并存：一个控件在「源码 / 预览」之间切；宽屏（≥1200px）默认双栏并记住上次选择（存 `settings` 表，与主题同源，便于进备份）。
- 从记录来的路径必须闭环：抽屉点笔记 → 笔记页顶栏出现「← 记录标题」→ 写完按 Esc 或点 ← **回到原抽屉并定位回原行**（R09）。这一条直接消掉用户说的"想关联笔记要切页"。
- 保存语义只剩一套：输入即标脏，1.2s 内无输入落盘，标题右侧状态小字是唯一反馈（不再有"保存中/已保存"两块地方各说一次）。

**空白态怎么表现**

- **右侧空白**：一个主按钮「新建笔记」+ 一句「笔记是 .md 文件，可以挂到多条记录上」。不再写「选择或新建一篇」。
- **左侧空白**：只留一行小字「还没有笔记」。不再给"点右上角"的指路（那个位置已经没有按钮）。
- **新建即落位**：点「新建笔记」直接在编辑器里建一篇空笔记，焦点在标题，不弹对话框、不切页。

## 五、验收清单（QA 用）

1. **旧文件兼容**：手写一个只含 `record_id: 12` 的 `.md` 放进 `notes/`，打开应用 → 笔记页与记录 #12 的抽屉都能看到这条关联；该笔记被编辑一次后，文件里出现 `record_ids`（含 12）。
2. **多对多计数一致**：一条记录挂 3 篇、其中 1 篇又挂另外 2 条记录 → 记录侧计数 = 3，笔记侧 chip 数分别 = 3 / 3 / 1；重启应用后数字不变。
3. **解除只解一条**：在笔记侧对第 2 个 chip 点 × → 该笔记剩 2 个 chip；另两条记录的笔记区各自少 1 项；被解除的那条记录的其余笔记不受影响。
4. **删除记录留痕**：删除 #37 → 相关笔记 chip 显示 `已删除记录（原 #37）`，颜色为 muted，点击 5 次无任何跳转；笔记文件 front-matter 里 37 仍在。
5. **文件搬家不丢关联**：在资源管理器把一篇挂 2 条记录的 `.md` 移到另一个分类目录并改名 → 重启 → 恢复"磁盘状态"（关联数仍是 2）；记录侧仍能列出该笔记。
6. **索引重建不抹关联**：构造 20 篇各挂 1–3 条记录的笔记，连续触发两次全量 `syncNoteIndex` → 关联总数与每篇的关联集合完全不变。
7. **抽屉首屏判据**：1360×860、6 个字段的表格行 → 抽屉打开后**不滚动**即可看到正文首行；截图存档对比。
8. **字段去重**：同一行里标题字段的值与抽屉大标题完全相同时，字段区不再出现该字段（可用截图里那条「设备名称」验证）。
9. **结构块折叠**：有 4 个子项 + 1 张表的记录 → 「结构」块默认收起，块标题显示 `4 个子项 · 1 张表`；点一次展开后 5 项都在。
10. **笔记页空间**：打开任意笔记，正文可编辑区域高度 ≥ 视口 60%；标题下方常驻控件不超过 1 行；页面无「保存」按钮（`grep` 不到 `note-save-btn`）。
11. **性能**：200 篇笔记、其中 50 篇有 1–3 条关联时，打开抽屉到笔记区出现条目 < 300ms，且 `listNotes` 单次调用完成，无 N+1。

## 六、待确认问题（每条给默认建议，不拍板就按默认做）

**Q1 · 关联的真相放哪？**
默认：写进 `.md` 的 front-matter（`record_ids`），索引不参与关联查询。代价是记录侧要扫一遍 `notes/` 目录（现状就是这么做的，200 篇量级无感）；好处是移动/改名/换机天然保关联，库挂了也能从文件恢复。
备选：新增 `note_record_link(rel_path, record_id)` 索引表。只有当笔记量级到几千篇、需要"按记录批量查笔记"时才有收益。

**Q2 · 抽屉里允许把字段折叠隐藏吗？**
默认：首屏只留 5 个高频字段，其余进「更多字段」。
**这是本 PRD 最可能被推翻的一条**——台账里字段本身就是主要内容，用户抱怨的"属性淹没标题正文"也可能只是**顺序问题**（正文排在 6 个区块之后），把正文提到前面就够，不必隐藏字段。若你否决，退化为：字段全显示、正文前置、结构块仍折叠。

**Q3 · 笔记页默认单栏还是双栏？**
默认：单栏；宽屏（≥1200px）默认双栏；选择记在 `settings` 表。理由：窄屏双栏下源码栏只剩半屏，长文写不动；但写 Markdown 表格/公式时对照预览是刚需，所以保留双栏且记住偏好。

**Q4 · 「已删除记录」占位要不要给清理入口？**
默认：占位保留、不自动清；在 设置 → 数据 里加「清理悬空引用」一次性全库扫描，报告"发现 4 处，已清理 4 处"（沿用 §9.3 的对策）。本次只做占位显示，清理入口排到 P2。

**Q5 · 抽屉里"转待办 / 转笔记 / 修改分类"这些兼容动作怎么处理？**
默认：收进 footer 的「⋯」菜单，**能力一个不删**。它们现在是 4 个平铺按钮压在正文下面，和"读这条记录"无关，但删掉会伤到正在用的流程。
